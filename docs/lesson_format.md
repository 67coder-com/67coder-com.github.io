# Формат урока · платформа 67coder

Этот документ описывает ровно то, что умеет сайт. Поля, которых здесь нет, сайт молча проигнорирует. Образец, где использован каждый тип экрана, — `sample/lesson-01.*.json`.

## 1. Файлы и где они лежат

```
content/cpp/
  course.json                структура курса: блоки, уроки, языки
  course.lv.json             названия блоков и уроков
  course.en.json
  lesson-NN.json             структура урока — ни одного переводимого слова
  lesson-NN.lv.json          тексты урока
  lesson-NN.en.json
  assets/
    lNN-имя.lv.svg           схемы со словами — по файлу на язык
    lNN-имя.en.svg
    lNN-<id шага>.jpg        иллюстрации без слов — одна на оба языка, имя по id шага
```

`NN` — номер урока с ведущим нулём: `lesson-07.json`, `l07-...`.

**Черновик и публикация.** Файл `course.json` ты не трогаешь — это делает агент Jules. Он ставит у урока `"draft": ["lv", "en"]`: урок появляется на сайте только по ссылке предпросмотра `https://67coder.com/?preview#/course/cpp/lv/lesson/N`, студенты его не видят. Когда автор всё вычитал, отдельная задача «Опубликовать главу» переносит языки в `"locales"`.

## 2. Файл структуры `lesson-NN.json`

```json
{
  "n": 1,
  "slug": "intro",
  "locales": ["lv", "en"],
  "steps": [
    { "id": "why-cpp", "kind": "theory" },
    { "id": "first-program", "kind": "example", "code": "...", "focus": "cout" }
  ]
}
```

Здесь лежит всё, что одинаково на любом языке: id и порядок экранов, тип, код, правильные ответы, ожидаемый вывод.

**id экрана** — латиница в нижнем регистре через дефис, по смыслу: `drop-namespace`, `find-bug-line`. Уникален в уроке, не меняется никогда — он стоит в адресе страницы. Номер экрана как id не используется.

## 3. Языковые файлы `lesson-NN.lv.json` / `.en.json`

```json
{
  "title": "Iepazīšanās ar C++",
  "module": "1. bloks · Pamodināšana",
  "steps": {
    "why-cpp": { "eyebrow": "...", "title": "...", "body": ["абзац", "абзац"] }
  }
}
```

Только строки, разложенные по тем же id. Набор id обязан совпадать во всех трёх файлах.

`body` — массив абзацев. Каждый абзац — 2–4 предложения.

**Код внутри текста — в обратных кавычках:** `` `cout` ``, `` `#include <iostream>` ``, `` `cout << "A" << endl;` ``. Сайт покажет его моноширинным шрифтом на подложке — и на экране, и в PDF. Работает во всех текстовых полях: `title`, `body`, `task`, `hint`, `caption`, `explain`, вариантах квиза, `points`, раскрывающихся блоках. Оборачивать нужно всё, что студент мог бы набрать в редакторе: ключевые слова, имена, операторы, целые команды. Не оборачивать: обычные слова, термины на латышском или английском, названия глав. В полях `code`, `starter`, `expected`, `solution`, `lines`, `blanks` обратные кавычки не нужны — там и так код.

## 4. Типы экранов

Общие текстовые поля у всех: `title`, `body` (массив абзацев), `eyebrow` (короткая метка над заголовком, необязательно), `more` (раскрывающиеся блоки, раздел 5).

| kind | Поля структуры | Поля текста | Что делает студент |
| --- | --- | --- | --- |
| `theory` | `image`, `imagePrompt` — необязательно | `title`, `body` | читает |
| `example` | `code`, `focus` — необязательно | `title`, `body`, `caption` | читает код с подсветкой |
| `explain` | — | `title`, `body`, `image`, `alt`, `caption` | смотрит схему |
| `predict` | `code`, `expected`, `focus` | `title`, `body`, `explain` | пишет прогноз вывода, потом сравнивает |
| `editor` | `lang`, `starter`, `expected`, `solution`, `code`, `stdin`, `requires`, `optional`, `hideExpected` | `title`, `task`, `hint`, `solutionNote` | пишет и запускает код |
| `clickline` | `code`, `answerLine` | `title`, `body`, `explain` | кликает строку с ошибкой |
| `parsons` | `lines` | `title`, `body`, `explain` | собирает программу из перемешанных строк |
| `blanks` | `code`, `blanks` | `title`, `body`, `explain` | заполняет пропуски в коде |
| `quiz` | `options`, `answer`, `code` | `title`, `body`, `options`, `explain` | выбирает ответ |
| `summary` | — | `title`, `points` | итог; кнопка «пройдено» |

`video` в шаблоне есть, но сейчас не используется.

### Подробности по полям

**`focus`** — фрагмент кода, который подсвечивается латунью. Подсвечивается только первое вхождение — на экране всегда одно выделение.

**`predict`.** `expected` — точный вывод программы. В `body` обязательно сказать, что это догадка и правильный ответ знать не нужно. Ответ «мимо» сайт показывает мягко и сразу раскрывает настоящий вывод.

**`editor`.**
- `lang` — `"cpp"`.
- `starter` — код в редакторе при открытии. Может быть пустой строкой.
- `code` — образец, который показывается **над** редактором (для заданий «перепиши и запусти»).
- `expected` — ожидаемый вывод. Если есть — сайт проверяет и показывает его в раскрывающемся блоке «Gaidāmā izvade». Это ещё и запасной вариант, если компилятор не загрузился.
- `hideExpected: true` — не показывать ожидаемый вывод (когда он сам по себе ответ).
- `solution` — полное решение, открывается по клику.
- `stdin` — текст, которым заполнено поле ввода. `false` — поля ввода нет, вывод на всю ширину. Если поле не указано — поле ввода пустое.
- `requires` — массив фрагментов, которые обязаны быть в коде студента. Пример: `["std::cout"]` — верный вывод без `std::cout` не засчитывается. Так проверяется приём, а не только результат.
- `optional: true` — необязательное задание для быстрых, на экране метка «Papilduzdevums».
- `hint` (в тексте) — подсказка, открывается по клику.

**`clickline`.** `answerLine` — номер строки с ошибкой, с единицы. В `explain` честно сказать, где компилятор показывает ошибку: clang иногда указывает на строку ниже.

**`parsons`.** `lines` — строки в **правильном** порядке, с отступами. Сайт сам их перемешает, одинаково для всех студентов. 4–8 строк.

**`blanks`.** В `code` пропуски размечены `[[1]]`, `[[2]]`… В `blanks` — допустимые ответы для каждого: `{"1": ["iostream"], "2": ["std"]}`. Пробелы при сравнении не учитываются. Длина поля подсказывает длину ответа — это нормально.

**`quiz`.** `options` в структуре — id вариантов в порядке показа: `["main", "first-line", "include"]`. `answer` — id правильного. Тексты вариантов — в языковом файле: `"options": {"main": "Funkcijā main", ...}`. Три варианта; неверные — правдоподобные ошибки новичка, не абсурд.

### Переопределение в языковом файле

Поля `code`, `starter`, `expected`, `solution`, `lines`, `blanks`, `image` можно указать в языковом файле — тогда они главнее структуры. Нужно, когда программа печатает текст на языке урока или схема содержит слова. По умолчанию держи их в структуре и делай вывод нейтральным.

## 5. Раскрывающиеся блоки

У любого экрана в языковом файле:

```json
"more": [
  {
    "kind": "archive",
    "title": "Kā Ingenuity lidoja ar atvērtā koda programmatūru",
    "body": ["абзац", "абзац", "абзац"],
    "sources": [
      { "title": "NASA NTRS — FPP: A Modeling Language for F Prime", "url": "https://ntrs.nasa.gov/citations/20220012872" }
    ]
  },
  { "kind": "deeper", "title": "...", "body": ["..."] }
]
```

`archive` — «Arhīva ieraksts», история. `deeper` — «Dziļāk», техническое углубление. Архивная справка — 3–6 абзацев, с источниками; без источника архивную справку не пишем. Блоки не участвуют в проверках и не обязательны для прохождения.

## 6. Картинки

### Схемы — SVG, рисует чат

Схема — это объяснение, а не украшение: поток данных, память, порядок выполнения, индексы, структура. На каждый язык свой файл, путь указывается в языковом файле: `"image": "assets/l01-compile-flow.lv.svg"`.

Сайт встраивает SVG прямо в страницу, поэтому шрифты сайта работают внутри схемы. Схема всегда лежит на тёмной подложке — в обеих темах сайта, как блоки кода.

| Что | Значение |
| --- | --- |
| Ширина | `viewBox="0 0 880 H"`, высота по содержанию, 200–420 |
| Подложка | `<rect width="880" height="H" rx="10" fill="#0D1117"/>` |
| Блоки | заливка `#151A22`, обводка `#2A313C`, толщина 1.5, `rx="8"` |
| Основной текст | `#D8D0C2`, от 16 |
| Подписи | `#8E887D`, 12, прописные, `letter-spacing="1.6"`, моноширинный |
| Линии и стрелки | `#B7B0A4` |
| Акцент | `#B99A61` — **ровно один элемент**, главное на схеме |
| Ошибка, неверный путь | `#CE8A78` |
| Успех, верный путь | `#7FB3A3` |
| Код в схеме | ключевые слова `#D1B784`, строки `#A9B79B`, числа `#C9A882`, комментарии `#8A8377` |

Шрифты задаются только через `style`, с запасным вариантом:
- текст: `style="font-family: var(--font-sans, Inter, sans-serif)"`
- код и подписи: `style="font-family: var(--font-mono, 'JetBrains Mono', monospace)"`

Обязательно: `<title>` и `<desc>` с полным текстовым описанием схемы. В языковом файле — `alt` тем же смыслом. Схема никогда не единственный носитель объяснения: то же самое сказано в `body`.

Нельзя: `<script>`, внешние картинки и шрифты, `<foreignObject>`, больше 4 блоков в ряд. На телефоне схема прокручивается вбок, а не сжимается, поэтому мелкий текст тоже нельзя.

### Иллюстрации — Nano Banana, промпт пишет чат

Иллюстрация — атмосфера и сцена: станция, дрон, маскот. **Без слов, букв и цифр** — генераторы картинок пишут текст с ошибками, и его нельзя перевести. Поэтому картинка одна на оба языка, а промпт `imagePrompt` лежит в файле структуры, у того шага, где она нужна.

**Путь указывать не нужно.** Иллюстрация шага всегда лежит в `assets/lNN-<id шага>.jpg` — например, у шага `why-cpp` урока 3 это `assets/l03-why-cpp.jpg`. Пока файла нет, в предпросмотре на месте картинки стоит карточка с промптом и кнопками «скопировать промпт» и «скопировать имя файла»; студенты на опубликованной главе не видят ничего. Поле `"image"` пишется только для схем SVG (они разные для каждого языка) и в редком случае, когда иллюстрация не JPEG.

Шаблон промпта (на английском — генератор лучше понимает):

```
Flat vector illustration, 16:9, for an online C++ course. [СЦЕНА: что изображено, 1–3 предложения.]
[Если есть маскот:] The course mascot — two square brackets [ ] facing each other with two round
cream eyes between them — [что он делает]. Use the attached image as the exact reference for the mascot.
Style: minimal, geometric, flat shapes, no outlines, no text, no letters, no numbers, no logos,
not cartoonish, calm and technical.
Palette strictly: background #090B0F, surfaces #151A22, warm grey #B7B0A4, cream #D8D0C2,
and a single accent of aged brass #B99A61 only on [один главный элемент].
Render the Martian ground in desaturated warm greys, not red.
```

Маскот всегда рисуется по приложенному эталону, его не описывают «своими словами». Картинки в главе — не больше двух-трёх: каждая требует ручной работы автора.

## 7. Компилятор

Код студента компилирует Clang (LLVM), собранный под WebAssembly, прямо в браузере. Стандарт C++20. Всё ниже проверено на этом компиляторе.

**Это 32-битная платформа.** Размеры типов:

| Тип | Байт | На onlinegdb и обычном Linux |
| --- | --- | --- |
| `short` | 2 | 2 |
| `int` | 4 | 4 |
| `long` | **4** | **8** |
| `long long` | 8 | 8 |
| `float` | 4 | 4 |
| `double` | 8 | 8 |
| указатель | **4** | **8** |

Никогда не пиши `expected`, где `sizeof(long)` равно 8. Для лекции 3 это подарок: студент вживую видит, что размер зависит от платформы.

**Исключений нет.** `try`, `catch`, `throw` не компилируются. `stoi` на мусорном вводе не бросает исключение, а аварийно завершает программу. Лекция 30 строится на проверке ввода и кодах ошибок; `try/catch` показывается только в блоке «Dziļāk» как статический пример (`example`), не в редакторе.

**Ввод не интерактивный.** `cin` и `getline` читают текст из поля ввода по порядку. Студент заполняет его до запуска; программа, прочитавшая больше, чем дано, получает конец ввода.

**Файлов пока нет.** `fstream` не работает. Понадобится к лекции 29 — до этого не ставь работу с файлами в редактор.

**Проверено и работает:** `iostream`, `string`, `vector`, `stoi` на корректном вводе, `climits`, переполнение `unsigned` (`0 - 1` даёт 4294967295), целочисленное деление (`5 / 2` даёт 2).

**Сравнение вывода:** пробелы в конце строк и пустые строки в конце не учитываются, всё остальное — буква в букву.

**Первый запуск** скачивает компилятор, это десятки мегабайт. Поэтому у каждой практики есть `expected` — текстовый ответ на случай, если компилятор недоступен.

## 8. Как сдавать файлы: формат ответа

Ответ с файлами делится на два раздела с заголовками — автор копирует их в разные места.

**`ДЛЯ GITHUB`** — всё, что попадает на сайт. Каждый файл — строка `Файл: путь` и сразу под ней блок кода:

    Файл: content/cpp/lesson-03.json
    ```json
    { ... }
    ```

    Файл: content/cpp/lesson-03.lv.json
    ```json
    { ... }
    ```

Сюда идут: три файла урока и SVG-схемы (`content/cpp/assets/l03-….lv.svg`). Файлы — целиком, без сокращений вроде «остальное без изменений»: агент записывает их ровно как есть. Весь раздел автор вставляет одной задачей на GitHub.

**`ДЛЯ MOODLE`** — описание подраздела, GIFT, задание. Этот раздел в GitHub **никогда** не попадает: репозиторий публичный, и вопросы экзамена стали бы видны студентам.

При правках после вычитки выдавай раздел `ДЛЯ GITHUB` снова целиком — со всеми тремя файлами, даже если изменился один.

## 9. Moodle-пакет лекции

Сайт про Moodle не знает, поэтому всё для Moodle сдаётся отдельным блоком. Это для автора — в JSON урока ничего из этого не попадает.

**Язык пакета — латышский, всегда и полностью:** описание, оба набора вопросов GIFT, задание. Английский пакет — только по прямой просьбе автора. Если ответ получается длинным — сокращай что угодно, но не латышский пакет.

### Что в пакете

На латышском (английский — только по просьбе):

1. **Название подраздела:** `N. Nosaukums` — как в программе курса.
2. **Описание подраздела** — HTML по шаблону ниже, целиком, со ссылками.
3. **Задание** — только если программа курса требует сдачу кода.
4. **Один блок GIFT** — внутри две категории: самопроверка и экзамен.

В подразделе лекции в Moodle только описание и тест «Pašpārbaude» (плюс задание, если оно есть). Ссылки на интерактивную главу и на PDF стоят в описании, отдельных элементов для них нет.

**Адрес сайта:** `https://67coder.com`. Ссылки:
- интерактивная глава — `https://67coder.com/#/course/cpp/lv/lesson/N`
- PDF-версия — `https://67coder.com/#/course/cpp/lv/print/N`

для EN — `/en/` вместо `/lv/`. N — номер главы без ведущего нуля.

### Вопросы GIFT

```
$CATEGORY: $course$/top/L01 Iepazīšanās ar C++

::L01-Q1:: Kur sākas C++ programmas izpilde?{
=funkcijā main#Pareizi: main ir ieejas punkts.
~faila pirmajā rindā#Pirmā rinda bieži ir \#include, un tā nav izpildāma komanda.
~rindā \#include#\#include apstrādā vēl pirms kompilācijas.
}
```

Правила:
- **Один блок на язык, две категории внутри.** Сначала строка категории самопроверки и 5 вопросов, затем строка категории экзамена и 5 вопросов. Пути вложенные: так Moodle может брать случайные вопросы сразу из всех глав части.
  - самопроверка, LV: `$CATEGORY: $course$/top/Pašpārbaudes/I daļa/LNN Nosaukums` — для глав 1–24, `II daļa` — для 25–32;
  - экзамен, LV: `$CATEGORY: $course$/top/Eksāmens/I daļa/LNN Nosaukums`, для 25–32 — `II daļa`;
  - EN: `Self-checks/Part I`, `Self-checks/Part II`, `Exam/Part I`, `Exam/Part II`.
  Номер главы с ведущим нулём.
- Имена вопросов: самопроверка `::LNN-Q1::` … `::LNN-Q5::`, экзамен `::LNN-E1::` … `::LNN-E5::`.
- **Символы `~ = # { } :` экранируются обратной косой** везде, включая обычное двоеточие в тексте вопроса. В C++ они на каждом шагу: `\#include`, `std\:\:cout`, `\{ \}`.
- Код в вопросе — через `[markdown]` и обратные кавычки: `` [markdown]Ko dara `cout`? ``. Пустых строк внутри вопроса нет — пустая строка в GIFT заканчивает вопрос.
- У каждого неверного варианта — пояснение после `#`: почему это не так.
- Смесь типов: выбор из 3–4, верно/неверно `{T}` / `{F}`, короткий ответ `{=точный ответ}` для «что выведет программа».
- Только пройденное — в этой лекции или раньше. Вопросы не копируют квиз с сайта: проверяют те же знания другими словами.

### Вопросы для экзамена — на понимание

Экзамен открытый: заочник пишет его дома, запретить материалы невозможно, поэтому они разрешены. Значит, вопрос не должен находиться поиском по тексту главы. Отсюда правила:

- **Новый код.** Каждый вопрос — на коде, которого нет ни в главе, ни в самопроверке. Ответ нельзя найти, его нужно вывести.
- **Рассуждение, а не определение.** Хорошие типы: что выведет программа; что изменится, если поменять строки или значение; какое одно исправление починит код; какой вариант даёт нужный вывод; почему этот код не компилируется. Плохие: «как называется…», «кто создал…», «в каком году…».
- **Неверные варианты — настоящие ошибки новичка**, а пояснение объясняет, где именно рассуждение сломалось.
- Ни блоки «Dziļāk», ни «Arhīva ieraksts» в экзамене не проверяются.
- Каждый код в вопросе проверен компилятором: вывод и «не компилируется» — фактические, а не предполагаемые.
