# Правила автора

Правила, которые автор курса дал во время работы над главами, — для всех следующих глав. Агент дописывает сюда правило, когда автор говорит «правило на будущее», «запомни как правило» или «так делай во всех главах».

Эти правила главнее `docs/instructions.md`: они новее и сказаны автором прямо. Если правило автора противоречит жёстким ограничениям — проверкам кода, ограничениям компилятора, «сначала объясни, потом проверяй», запрету на Moodle в репозитории, — агент не записывает его молча, а говорит автору, с чем оно расходится.

## Правила

- **Неинтерактивный `git push` (глава 3).** Команду `git push` всегда запускать с переменными окружения `$env:GCM_INTERACTIVE='never'; $env:GIT_TERMINAL_PROMPT='0'`. Если аутентификация не сохранена, команда не зависает в ожидании ввода, а сразу завершается ошибкой — в этом случае сообщить автору.
- **Без запуска браузера (глава 3).** Агент не запускает локальный браузер. В отчёте давать ссылку на предпросмотр (на сайте / GitHub) — автор открывает внешний браузер сама.
- **Цветные иллюстрации в фирменной гамме (глава 8).** Во всех главах вводные иллюстрации должны быть цветными в кинематографичном векторном стиле 16:9 с фирменной палитрой: глубокий тёмный слейт (#090B0F, #151A22), тёплый золотистый янтарь (#B99A61, #D1B784), приглушённый шалфейный циан (#7FB3A3) и чистый светлый крем (#D8D0C2). Стиль: чистая векторная эстетика, атмосферное освещение базы, маскот строго по эталону [ o o ].
- **Проверка только текущей главы (глава 11).** При локальной разработке компилировать только программы текущей главы: `$env:CLANG_DIR='C:\Data\67coder\clang'; node tools/compile-check.mjs <N>`, чтобы не тратить время на повторную компиляцию уже проверенных прошлых глав курса.
- **Одноуровневые нумерованные списки в заданиях (глава 11).** В формулировках задач (`task`), состоящих из нескольких шагов, все шаги оформлять строго единым нумерованным списком `1. `, `2. `, `3. ` без вложенных маркированных списков с отступами (`   - `), иначе парсер сайта склеивает текст задания в один сплошной абзац.
- **Единый скрипт публикации (глава 14, уточнено в главе 15).** Публикация любой главы выполняется строго неизменной командой: `node tools/publish.mjs` (без номера главы в аргументах). Скрипт сам автоопределяет черновик или изменённую главу, переносит её из draft в locales в `course.json`, делает git add, commit, push и собирает PDF для Moodle. Благодаря неизменной командной строке Antigravity запоминает разрешение «Always allow» и не переспрашивает на новых главах.
- **Обязательный блок «Синтаксис» и подробные объяснения (ревью курса).** При вводе любой новой синтаксической конструкции C++ (циклы while/for, массивы, векторы, функции, ссылки, структуры struct, строки string, манипуляторы iomanip, потоки fstream и т.д.) обязательно оформлять блок «Синтаксис» строго в формате платформы: `"syntax: {часть1} ключевое_слово {часть2};\n- часть1: ...\n- часть2: ..."` с расшифровкой каждой фигурной скобки `{...}` на языке файла (в LV — латышские названия в скобках, в EN — английские). Шаги теории не должны быть «пустыми» или поверхностными: обязательны подробный связный текст с интуицией, правилами, подводными камнями (`!>`), маркированными списками и контекстом миссии.
- **Эластичность токенов requires, однозначность blanks и явный cin / stdin (ревью глав 1–8).** Не использовать в `requires` составные строковые выражения с пробелами или альтернативным синтаксисом (например, `station + "/" + channel`), которые штрафуют студента за пробелы или использование `'/'`; проверять только уникальные ключевые фрагменты (имена переменных, вызовы методов вроде `full_channel`, `.length()`), а вычисления проверять по `expected`. В тестах пропусков `blanks` указывать строго однозначные типы без ошибочной псевдовариативности (например, недопустимый `char` для строкового литерала). Для всех шагов с `cin` и `getline` обязательно задавать свойство `"stdin": "..."` в структуре, а в шагах `predict` с потоковым вводом всегда явно показывать студенту входные данные в тексте экрана выноской (например, `> **Console input:** `3 4``). В ранних главах строго соблюдать карантин тем: не требовать ручного ввода синтаксиса `char` ('A') и `bool` (true) до Главы 6 — давать их готовыми в шаблоне.
